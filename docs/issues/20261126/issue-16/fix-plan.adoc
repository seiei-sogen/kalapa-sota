= issue #16 ワークツリーの一覧を左の列に表示する: 計画

事前調査は link:preliminary-investigation.json[] にある。issue の本文が、データの形とコミットの順を決めている。この計画は、それをいまのコードに当てはめ、本文が決めていない細部を決める。

== 目的

左の列の一番上に *WORKTREES* を足し、ワークツリーを 1 行ずつ出す。開いているワークツリーに ● を付ける。その下に *BRANCHES* を置く。

終わりの条件は、次のとおり。

* `cargo test` が通る。
* Xvfb で `fixture-repo` を開くと、WORKTREES の 3 行と 1 行目の ● が写る。`click_branch_row 0` で `feature-a` に切り替わる。
* `fixture-repo-worktree-review/sub` を渡して起動すると、● が `fixture-repo-worktree-review` の行と、BRANCHES の `worktree-review` に付き、タイトルが `kalapa - <そのルートのパス>` になり、`doctor_kalapa.sh` が 0 で終わる。
* 既存のレシピ `view-history.md`、`switch-branch.md`、`push-current-branch.md` と、`scripts/verify_on_xvfb.sh` が通る。
* 読み直し 1 回の git のプロセスが 5 である。

== 現状

* 左の列は BRANCHES だけである。`render_local_branch_panel` が、列の枠と見出しと行を 1 つの関数で作る。
* `RepositoryWindow` は `repository_path: PathBuf` を持ち、起動時の引数をそのまま入れる。タイトルも引数そのままである。
* `read_repository_snapshot` は `log`、`for-each-ref`、`rev-parse --is-inside-work-tree`、`status` の 4 回、git を呼ぶ。
* 性能の基準。`main` を `GIT_TRACE=<絶対パス>` 付きで起動し、`leave_and_return_to_window` の前後で `trace: built-in: git` の行を数えると、8 行増えた。Xvfb では、離れるときと戻るときの 2 回、読み直しが走るからである。読み直し 1 回あたりは 4 である。
* git 2.43.0 で、`git worktree list --porcelain -z` の形、`rev-parse --show-toplevel` と `--absolute-git-dir` の動きを確かめた。出力は事前調査にある。
* リスク。macOS の一時ディレクトリのパスは、正規化しないと git の返すパスと合わない。ブランチの行が下へずれるので、検証スクリプトの座標を同じコミットで直す。

== テスト

最初に書く、失敗するテストは、コミット 2 の `worktrees_round_trip_tests` の 2 つである。

* fixture のサブディレクトリを渡した `resolve_worktree_root_path` が、fixture のルートを `canonicalize` したパスを返す。
* bare リポジトリを渡した `resolve_worktree_root_path` が、そのリポジトリを `canonicalize` したパスを返す。

続けて、次の順に書く。

* `parse_worktree_list_porcelain_tests`: ブランチ、detached、bare、`prunable` 付き、`locked` 付き、空白と改行を含むパス、壊れた出力 (`worktree` で始まらないレコード、チェックアウトの属性がないレコード)。
* `worktrees_round_trip_tests`: `git worktree add` のあと `read_worktrees` が 2 つを返し、チェックアウトが合う。リンクされたワークツリーのサブディレクトリの `resolve_worktree_root_path` が、`read_worktrees` の返すパスと等しい。bare リポジトリの `resolve_worktree_root_path` が、bare の行のパスと等しい。ディレクトリを消したワークツリーが一覧に残る。リンクされたワークツリーを 1 つ持つ bare リポジトリの `read_repository_snapshot` は、`worktrees` の先頭が `Bare` で、`changed_files` が空である。
* `worktree_checkout_label_tests`: 3 つの場合。

fixture は `create_fixture_repository` で作る。この関数は、一時ディレクトリの下の `kalapa-<テスト名>-<PID>` をリポジトリにする。リンクされたワークツリーと bare リポジトリは、リポジトリの外の `kalapa-<テスト名>-<用途>-<PID>` に作り、テストの始めと終わりに消す。

== 確認

* CI は、調べた時点の `main` にない。#14 が着地していれば、macOS の `cargo test` が走る。
* 手元で `cargo test` と `cargo build` (警告なし) を通す。コミット 3 だけは、`parse_worktree_list_porcelain` をテストしか呼ばないので、`cargo build` が dead code の警告を出す。コミット 4 で消える。`#[allow]` は付けない。
* `target/debug/kalapa <ない場所>` が、git のメッセージを標準エラーに出して終了コード 1 で終わることを見る。
* bare でないリポジトリの `.git` を渡して起動し、履歴が出て、● がどの WORKTREES の行にも付かないことを見る。
* Xvfb の live と perf は、issue の「検証」のとおりに行う。perf は、`leave_and_return_to_window` の前後で増える行が 10 (読み直し 2 回 × 5) であることを見る。11 以上なら不合格とする。
* 作り直す生成物は `docs/images/repository-window.png` である。
