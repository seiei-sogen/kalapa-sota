= issue #17 ワークツリーをクリックして、ウィンドウで開く: 計画

事前調査は link:preliminary-investigation.json[] にある。

== 目的

WORKTREES の行をクリックすると、ウィンドウがそのワークツリーを開く。

終わりの条件は、次のとおり。

* クリックすると、● がその行へ移り、コミット履歴、BRANCHES、CHANGES、タイトルがそのワークツリーのものになる。
* そのあと BRANCHES の行をクリックすると、開いているワークツリーのブランチだけが切り替わる。
* 読めないワークツリーの行をクリックすると、赤い帯にエラーが出て、● は動かない。
* `cargo test` が通る。issue の live の 4 つと perf が通る。

== 現状

* `render_worktree_section` の行は、クリックもホバーも持たない。関数は `cx` を受け取らない。
* `RepositoryWindow` は `opened_worktree_root_path`、`snapshot`、`commit_graph`、`last_git_error` を持つ。タイトルは `main.rs` が起動時に 1 度だけ決める。
* `read_repository_snapshot` は git を 5 回呼ぶ (#16 の perf で確かめた)。
* リスク。検証スクリプトの `git_in_repository` と `record_git_state` は、起動時のパスに対して働く。切り替えたあとの状態は `git -C <パス>` で読む。

== テスト

issue のとおり、足すテストは git の前提を固定するもので、新しいコードを書く前から通る。先に赤くはならない。`open_worktree_in_window` は `Window` と `Context` が要るので、単体テストを書かない。証拠は live と perf である。

* リンクされたワークツリーのパスで `switch_local_branch` を呼ぶと、そのワークツリーの現在のブランチだけが変わる。メインのワークツリーのブランチは変わらない。
* メインのワークツリーが使っているブランチへの `switch_local_branch` は `Err` を返し、どちらの HEAD も動かない。
* リンクされたワークツリーのパスで読んだ `read_repository_snapshot` は、そのワークツリーのブランチを現在のブランチとし、そのワークツリーの変更だけを返す。

== 確認

* CI: macOS の `cargo test`。手元でも `cargo test` と、警告のない `cargo build` を通す。
* live: issue の 4 つを、1 つの起動で続けて行う。`click_worktree_row 2`、`click_branch_row 2`、`click_branch_row 3`、`fixture-repo-detached` を消して `click_worktree_row 1`。それぞれスクリーンショットと `git -C` の出力を残す。
* perf: `GIT_TRACE=<絶対パス>` 付きで起動し、`click_worktree_row 2` の前後で増えた `trace: built-in: git` の行を数える。5 以下なら合格とする。基準は読み直し 1 回の 5 である。
* 既存のレシピ `view-worktrees.md` の 1 つ目と 2 つ目の手順と、`scripts/verify_on_xvfb.sh` が通る。
* 作り直す生成物はない。`docs/images/repository-window.png` は、画面が変わらないので撮り直さない。

== 計画と違うこと

* コミット 2 のあと、コミット 3 までは、`cargo build` が dead code の警告を 1 つ出す。`open_worktree_in_window` を呼ぶのは、コミット 3 の行のクリックだからである。警告はコミット 3 で消える。
* `SKILL.md` の関数の表で、`git_in_repository` の説明を「開いているリポジトリ」から「`launch_kalapa.sh` が開いたワークツリー」に直した。ワークツリーを切り替えると、「開いている」がどちらを指すか分からなくなるからである。
* README の「ワークツリーを開く」の節に、読めないワークツリーをクリックしても元のワークツリーを開いたままになる、という 1 文を足した。issue の「作る変更」が決めている動きで、利用者が出会うからである。
* `scripts/verify_on_xvfb.sh` は、ディスプレイを `:99` から `:95` に、`app_root` をリポジトリの絶対パスに置き換えた写しで走らせた。この作業で使ってよいディスプレイが 92 から 98 だったからである。ほかの行は変えていない。
* live のスクリーンショット 4 枚を link:live-evidence/[] に置いた。
* コードレビューのあと、テストの補助関数 `path_outside_fixture` を `src/git_cli/fixture_repository/path_outside_fixture.rs` へ移した。計画は `pub(super)` で借りるとしていたが、テストのファイルが隣のテストのファイルに依存する形になるからである。
* コードレビューの指摘のうち、この PR で直さなかったものは、issue にした。`.git` を失ったワークツリーの行をクリックすると外側のワークツリーが開くこと (#25)。直すとクリック 1 回の git のプロセスが perf の上限 (5) を超えるので、所有者の判断が要る。開くのに失敗しても消えたワークツリーの行が残ること (#26)。push の途中で切り替えたときの結果の出し方は、issue #17 が「変えないこと」としているので、そのままにした。
